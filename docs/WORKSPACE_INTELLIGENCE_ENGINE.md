# Workspace Intelligence Engine

Phase 1 of the Humanity Union Civic Assistant introduces a deterministic **Workspace Intelligence Engine**. It understands the platform's constitutional civic architecture and guides participants through Capability 02 workflows without LLM calls, free-form AI responses, or automatic civic mutations.

## Architecture

```
RequestIdentity + Member Profile + Participation Area
        ↓
Capability02 Integration View (when initiative selected)
        ↓
Workspace Intelligence Context
        ↓
Constitutional Rule Engine (WORKSPACE_INTELLIGENCE_RULES)
        ↓
Priority-sorted WorkspaceSuggestion[] + WorkspaceBlockedAction[]
        ↓
GET /api/v1/workspace-assistant/intelligence
        ↓
Workspace Assistant UI (display-only navigation guidance)
```

### Module location

`apps/api/src/modules/workspace-intelligence/`

| File                                     | Role                                               |
| ---------------------------------------- | -------------------------------------------------- |
| `workspace-intelligence.context.ts`      | Builds participant-visible civic context           |
| `workspace-intelligence.rules.ts`        | Deterministic pipeline, section, and blocked rules |
| `workspace-intelligence.registry.ts`     | `WORKSPACE_INTELLIGENCE_RULES` registry            |
| `workspace-intelligence.explanations.ts` | Constitutional explanation strings                 |
| `workspace-intelligence.service.ts`      | Orchestration, sorting, privacy sanitization       |
| `workspace-intelligence.routes.ts`       | Authenticated HTTP surface                         |
| `workspace-intelligence.types.ts`        | Domain types                                       |

## Rule engine

Every rule in `WORKSPACE_INTELLIGENCE_RULES` has:

- `id` — stable rule identifier
- `description` — human-readable purpose
- `stage` — civic pipeline stage or `workspace`
- `priority` — default priority class for rule output
- `evaluate(context)` — pure function returning `WorkspaceSuggestion[]`

Rules inspect **existing civic state only**. Examples:

| Condition                             | Suggestion                       |
| ------------------------------------- | -------------------------------- |
| Initiative draft (steward)            | Publish Initiative               |
| Published, no analysis                | Begin Collaborative Analysis     |
| Analysis complete, no proposal        | Create Improvement Proposal      |
| Accepted proposal, no revision        | Open Revision                    |
| Published revision, no closed session | Prepare Decision Session         |
| Closed session, no closed decision    | Create Collective Decision       |
| Open decision, eligible, no vote      | Cast your vote                   |
| Closed decision, no CAP               | Generate Civic Action Package    |
| CAP exists, no delivery               | Deliver Civic Action Package     |
| Delivery exists, no response          | Record Official Response         |
| Active accountability                 | Continue Accountability Timeline |
| Tracking complete, no impact          | Create Public Impact             |
| Verified impact, no archive           | Archive this initiative          |

Blocked rules explain **why** an action cannot proceed (open decision session, incomplete tracking, pending participation transition, not steward, not eligible).

## Suggestion priority

Each `WorkspaceSuggestion` carries a priority:

1. `critical`
2. `important`
3. `normal`
4. `informational`

The service sorts suggestions by this order before returning them. The first item becomes `topRecommendation`.

## Constitutional explanations

Every recommendation includes a `constitutionalReference` string describing **why** the action exists in civic terms—for example:

> You can create a Collective Decision because the Decision Session has already closed.

Explanations are authored in `workspace-intelligence.explanations.ts`. They are not generated by AI.

## API

```
GET /api/v1/workspace-assistant/intelligence?initiativeId=&section=
```

Authenticated. Returns:

- `context` — full `WorkspaceIntelligenceContext`
- `currentCivicStage`
- `currentResponsibilities`
- `suggestions` — priority-ordered
- `blockedActions`
- `nextCivicMilestone`
- `topRecommendation`
- `constitutionalSummary`

## Frontend integration

The workspace assistant sidebar (`WorkspaceIntelligencePanel`) renders:

- Top recommendation
- Secondary recommendations
- Blocked items
- Current civic stage and next milestone
- Constitutional explanation

Recommendations link to `relatedRoute` paths. **No automatic navigation** and **no chat input** are performed.

Intelligence refetches when the workspace section, initiative, pipeline state, profile, or participation area changes (via query parameter updates on navigation).

## Privacy

The engine uses participant-visible records only. Responses must never expose private votes, other participants' data, emails, JWT material, or internal auth fields. `sanitizeWorkspaceIntelligenceResponse` enforces this at the service boundary.

## Verification

```bash
npm run verify:workspace-intelligence
```

Runs three consecutive passes and verifies context creation, rule evaluation, priority ordering, blocked detection, pipeline recommendations, section-aware suggestions, constitutional explanations, and absence of AI providers.

## Future AI integration (deferred)

Phase 2 may introduce an external LLM **only as an augmentation layer**. The intelligence engine remains authoritative:

```
Workspace Context
        ↓
Workspace Intelligence Engine   ← authoritative, deterministic
        ↓
Constitutional Rule Engine
        ↓
Capability02 Integration
        ↓
LLM Provider                    ← explanations only, human-reviewed
        ↓
Human-reviewed Recommendation
```

**The LLM must never replace the Intelligence Engine.** It may enrich explanations after deterministic suggestions are computed. No autonomous agents, automatic publishing, voting, or delivery are permitted in any phase without explicit participant action.

## Explicit exclusions (Phase 1)

- No OpenAI, Anthropic, Gemini, Ollama, or MCP
- No prompt engineering or free-form generation
- No automatic civic mutations
- No changes to Capability 02 workflow implementations
